# 历史更新记录

### 【2026/09/10 更新 v2.1.0】
1) 新增项目标签：作者可为自己的项目设置标签，便于按类别检索
   · `pb tag` 查看标签库与用法
   · `pb set <名称> tag <标签1> [标签2]...` 批量设置项目标签，填「无」清空
   · `pb tag mark <标签> <项目1> [项目2]...` 批量为多个项目追加同一标签
   · `pb list tag <标签>` 按标签筛选项目列表
2) 新增项目存储回滚：可将项目存储回滚至本地备份中的任一份数据库快照
   · `pb rollback <名称> list` 查看可回滚的备份
   · `pb rollback <名称> diff <编号> [目标]` 对比备份与当前数据
   · `pb rollback <名称> <编号> <目标>` 执行回滚，目标可为 all／global／用户ID
   · 回滚全程持有项目存储锁，二次确认期间数据若被改写会自动取消本次回滚
3) `pb help` 重新分组：折叠部分命令分类
4) 修复 `pb list` 中作者名过长导致的排版错乱：超出列宽的作者名直接截断，仅显示靠前内容

### 【2026/09/07 更新 v2.0.0】
1) 存储数据迁移至 SQLite：项目存储、跨项目存储库、代码缓存、项目统计不再保存于 yml
2) 进程锁改为项目级：不同项目的执行完全并行，只有同一项目、或共享同一存储库的项目之间才需要排队
3) `bk`、`pb` 的存储类指令与执行进程共用同一套锁：指令不会再与跑到一半的项目互相覆盖
4) 项目存储的用户数量与大小改为涵盖全部平台，此前只统计 QQ
5) 新增 `pb status`：查看数据库连接与完整性、进程占用、备份情况、数据目录占用
6) 存储库名称等不再拒绝 `null`、`~` 等 YAML 保留字
7) 修复存储库所有权转移实际未生效的问题（写入了错误的槽位）
8) 修复项目改名后丢失全部关联存储库的问题
9) 数据备份新增数据库快照，与同批次 yml 存放于同一目录

⚠️ 升级须知：本版本新增运行时依赖 `org.xerial:sqlite-jdbc`，由 Mirai Console 自动下载。
启动 2.0.0 会重写 `ExtraData.yml` 并丢弃其中的 statistics 段，**旧数据迁移脚本必须在此之前运行**，
详见 `scripts/migrate_yml_to_sqlite.py`。
